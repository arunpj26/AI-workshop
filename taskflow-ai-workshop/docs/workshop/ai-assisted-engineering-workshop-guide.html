Workshop feature

Add optional priority filtering to GET /api/tasks. Values: LOW, MEDIUM, HIGH. Omitted parameter preserves current behaviour; invalid values return HTTP 400. Resolve open questions in docs/requirements/acceptance-criteria.md before coding.

Human checkpoints: approve the plan before code changes; approve external actions such as commit, push, and PR creation explicitly.

Component roles

  • Instructions: persistent repository/path-specific guidance.
  • Prompts: reusable task starters.
  • Agents: role-based workflows.
  • Skills: reusable step-by-step procedures explicitly referenced by agents.
  • MCP: approved external tools/context; Jira access uses Atlassian MCP and OAuth.
  • Hooks: supported lifecycle automation/guardrails, not a complete security boundary.

Security and hooks

The hook registers enforce-network-policy.cjs for preToolUse. It blocks a limited set of obvious shell network commands and direct web-fetch calls. It cannot reliably block indirect network access, all MCP calls, IP geolocation, or device location.

Real enforcement: use administrator-managed policies, network firewalls, OS/container sandboxing, and approved tool permissions. Test hooks in a disposable workspace; hook support varies by runtime/version.

Jira endpoint: https://mcp.atlassian.com/v2/mcp. Complete OAuth in the supported client; access follows the signed-in account and org policy. Never commit secrets.
